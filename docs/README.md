# Карта света

Карта улиц Донецка: где есть свет, где нет, и насколько этому можно верить. У каждой отметки есть время и уверенность, поэтому старые данные не выдают себя за свежие.

Живая версия: https://lerk.tech/svet/

## Как считается статус улицы

Код: `model.py`, проверки: `tests/test_model.py`.

- Статус улицы берётся из самой новой отметки. Свежее сообщение перекрывает любое старое.
- Уверенность в отметке падает вдвое за 90 минут для «свет есть» и за 4 часа для «света нет»: свет любят то давать, то снимать, поэтому «есть» устаревает быстрее.
- Каждый человек считается один раз, по своей последней отметке. Второй человек с тем же ответом за последние 3 часа добавляет к уверенности четверть, спор (другой человек сказал обратное незадолго до последней отметки) снижает её на 40 %.
- Источникам разное доверие: чат, бот и датчик 1.0, кнопка на карте и комментарий со страницы 0.85.
- Уровни: от 0.6 «уверенно», от 0.3 «скорее всего», ниже «давно не подтверждали». Через сутки без подтверждения улица снова серая, но запись остаётся в базе.
- На карте цвет блёкнет с уровнем. Если отметка выцвела, цвет даёт график (Киевский район), он тоже рисуется блёклым. Если нет ни графика, ни отметки, улица серая.

## Как открыть локально

```bash
python3 server.py
```

Дальше `http://127.0.0.1:8765/`. Файл с диска напрямую не открывать: браузер не отдаст `data/streets.geojson`. Зависимостей нет, нужен только Python 3 (в нём есть sqlite3). Адрес и порт: `KARTA_HOST`, `KARTA_PORT`.

## Что хранится

`data/karta.db` (SQLite, режим WAL), таблица `reports`: улица, статус, время, вид (`chat`, `bot`, `sensor`, `button`, `comment`), название чата, короткий хеш человека, текст до 240 символов. Имя, телефон, IP и квартира не хранятся: человек превращается в хеш с солью из `data/secret.json`. База и секрет в git не попадают.

Старый `data/live-reports.json` при первом запуске переносится в базу.

## API

| Запрос | Что делает |
| --- | --- |
| `GET /api/live` | статус каждой улицы за последние сутки: `status`, `at`, `age_min`, `confidence`, `level`, `sources`, `conflict`, `source`; `now` для сверки часов |
| `POST /api/mark` | кнопка на карте: `{"key", "status", "segment"}` |
| `POST /api/comments` | текст со страницы: `{"text", "source"}`, улица и статус ищутся в тексте |
| `POST /api/ingest` | для читалок чатов и датчиков, нужен заголовок `X-Ingest-Token` из `data/secret.json` |

Публичные POST ограничены 30 запросами с одного адреса за 10 минут. Тот же человек с тем же ответом по той же улице за 2 минуты записывается один раз. Сообщения старше суток не принимаются.

Тело `/api/ingest`:

```json
{"text": "на Артёма нет света", "source": "Киевский чат", "sender": "12345", "ts": 1792603861, "ext_id": "tg:-100123:456"}
```

`ext_id` защищает от повторов при перезапуске читалки. Для датчика вместо `text` можно прислать `{"kind": "sensor", "key": "артема", "status": "off", "sender": "esp-1", "source": "датчик"}`. Любой мост (Telegram, MAX, свой бот) может писать сюда же.

Наружу сервер отдаёт только страницу, `vendor/` и четыре файла данных карты. Код, база и секреты закрыты.

## Автоприём из чатов Telegram

`scripts/tg_ingest.py` читает перечисленные чаты и шлёт сообщения про свет на `/api/ingest`: при старте добирает последние часы, дальше слушает новые.

1. `pip install -r requirements-reader.txt`
2. `api_id` и `api_hash` на https://my.telegram.org (API development tools)
3. `data/chats.json` по образцу `data/chats.example.json`: чаты, адрес `/api/ingest`, при удалённом запуске токен. Нужен аккаунт, который состоит в этих чатах. Бот без прав администратора обычные сообщения группы не видит.
4. Первый запуск вручную: `python3 scripts/tg_ingest.py --check`. Telethon спросит телефон и код, сессия ляжет в `data/` и в git не попадёт.
5. Дальше обычным процессом (systemd). С российского сервера Telegram не отвечает, нужен `proxy` в конфиге (SOCKS5) или запуск на сервере за границей с адресом `https://lerk.tech/svet/api/ingest`.

## Как обновить линии улиц

Overpass, граница Донецка в OSM (отношение 1413957, область 3601413957):

```bash
curl -fsSL --max-time 200 -A "karta-sveta-local/0.1" -o /tmp/donetsk-streets.json \
  --data-urlencode 'data=[out:json][timeout:160];area(3601413957)->.a;way["highway"~"^(trunk|primary|secondary|tertiary|residential|living_street|unclassified)$"]["name"](area.a);out geom;' \
  "https://overpass-api.de/api/interpreter"
python3 scripts/build_streets.py /tmp/donetsk-streets.json
```

Скрипт режет длинные линии кусками около 500 метров и склеивает соседние короткие обрывки, если их концы ближе 40 метров и вместе они не длиннее 500 метров. Пишет `data/streets.geojson` и `data/streets-index.json`. Данные улиц © участники OpenStreetMap (ODbL).

## Выкладка

Сейчас: VPS с nginx, служба `karta-sveta` слушает только `127.0.0.1:8765`, nginx проксирует `/svet/` на неё. Файлы в `deploy/`: `karta-sveta.service` (systemd, пользователь `www-data`, запись только в `data/`) и `nginx-karta-sveta.conf` (кусок для `server`). Обновление:

```bash
cd /var/www/karta-sveta && git pull --ff-only && systemctl restart karta-sveta
```

База лежит в `data/`, `git pull` её не трогает.

## Чего ещё нет

- Графики по другим районам, кроме Киевского: нужен автосбор с сайтов и каналов Донецкэнерго.
- Вывод по соседним улицам и подстанциям, когда по улице нет данных.
- Датчики-«пульс» (роутер, ESP32): приём уже есть, `kind: sensor`, самих датчиков нет.
- Статус по участку улицы: сервер уже сохраняет `segment` из кнопки, но считает по всей улице.
